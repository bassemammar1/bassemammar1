## 🤖 How I Use AI

I treat a language model as one dependable component of a system, not as a magic box. In my projects it plays three roles:

<table>
  <tr>
    <td>🩺 <b>Coach</b></td>
    <td>Turns a person's habit entries into short daily and weekly feedback (<a href="https://github.com/bassemammar1/health-logger">Health Logger</a>).</td>
  </tr>
  <tr>
    <td>🧪 <b>Reviewer</b></td>
    <td>Returns structured findings for a source file: severity, issue, suggestion, line, rule and category (<a href="https://github.com/bassemammar1/ai-generrator">AI Code Reviewer</a>).</td>
  </tr>
  <tr>
    <td>💬 <b>Summarizer</b></td>
    <td>Condenses missed messages into a two-line catch-up (<a href="https://github.com/bassemammar1/chatting-app">Chat App</a>).</td>
  </tr>
</table>

The rules I follow:

- 🧾 **Structured output:** ask for fixed JSON fields when the app depends on the answer, and validate them before they are stored or shown.
- ✂️ **Bounded answers:** keep responses short so they fit the interface, for example a summary of at most two lines.
- 🎯 **Low temperature:** use a low setting where consistency matters more than variety.
- 🔌 **Replaceable provider:** keep the model behind one small class, so the model, endpoint and settings can change without touching the rest of the app.
